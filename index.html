Problem

Curd packaging line ran at 44% OEE — far below world-class 85% benchmark. Team missed demand targets daily with zero visibility into why. ₹2.8Cr/qtr bleeding out silently.

Discovery

Through user research and customer journey mapping, identified delayed downtime classification as root cause. Planned downtimes (CIP, meal breaks) were consistently overrunning with no one tracking the overruns.

Decision & Solution

Applied Pareto Analysis — top 3 causes were all planned downtime overruns. Built real-time RCA dashboard giving production manager full visibility into which downtime caused each delay, per machine, per shift.

Impact

OEE 44%→85% (world-class). Downtime 3.35→0.38 hrs/day (↓91%). ₹2.8 Cr recovered per quarter. No new machines or headcount.

Problem

Operators manually assigned downtime reasons across 20–50 records per shift — increasing effort and reducing OEE reporting accuracy and operational visibility.

Discovery

Validated via operator interviews, shop-floor observations, and Zipy session analytics before committing any engineering effort.

Constraints
  • Data integrity risk during bulk updates
  • Operator training for new workflow
  • Audit trail requirements
Decision & Impact

Designed bulk assignment collapsing multi-step entry into single action. Defined validation rules and audit controls. Operator effort ↓60%, corrections ↓40%, 1.5 hrs/day saved.

Problem

Fragmented popup UI caused operators to skip downtime entries during live production — creating data gaps that broke OEE reporting and masked recoverable losses.

Discovery

Identified via shop-floor observations and Zipy session recordings. Confirmed the pattern across multiple plants before scoping the solution.

Decision

Balanced operator efficiency with production traceability — replaced modal popups with inline interactions without compromising data capture requirements.

Impact

Entry time ↓45%, data completeness ↑30%, QA errors ↓80%, 89.1 hrs/month saved. Redesign became the UX baseline for all new plant deployments.
